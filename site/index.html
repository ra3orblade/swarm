See every agent. Stop the collisions.

One daemon watches every agent session on your machine, keeps the ledger of who holds which task, worktree and port, spawns and gates agents of its own — and turns “never do X” from a line in CLAUDE.md into a permission decision.

Local-first. No account, no telemetry, nothing added to your repositories.

Observe

Run four agents at once and you lose the thread by lunchtime. Swarm reads the hooks and session logs they already write — nothing to instrument, nothing added to your repo.

Fleet, live

Every agent session on the machine, streaming: agent, branch, the tool it is running right now, model, output tokens, context size, cost, age — across every repository, with zero instrumentation. A session that starts repeating a failing command gets a Stuck badge and a notification; nothing is ever interrupted.

Outcomes

Did the work survive? Sessions join to a branch, the branch to its PR, the PR to merged or reverted — scored per model and per agent: merge rate, median time to merge, dollars per merge. The one number that says which agent is worth it.

Collisions, before they happen

A live graph of running sessions against the files they touch. A file two sessions hold with at least one writer turns red — that's tomorrow's merge conflict, on screen while you can still move someone.

  • Replay & resume — step through an agent's tool calls with full input and output; a session that died gets Resume where it died.
  • Session detail — the reasoning stream beside the numbers: cost per turn, cache hit rate, thinking share, tool mix.
  • Timeline — session lanes per project, coloured by agent, a tick per turn, a claims lane underneath.
  • Spend — by day, agent, model, project and task, while it is still today.
  • Stats & search — all-time totals and streaks; full-text memory over handoffs, incidents, gates and what sessions said.
  • ⌘K everywhere — a palette over every view, project and session, falling through to search.

Coordinate & drive

Swarm doesn't only watch agents — it starts them, in a claimed worktree, under the same rules as your interactive sessions, and tells you what actually came out.

Run it, then get a verdict

Hand Swarm a task and it starts an agent on it, in a worktree of its own. Hand it a whole backlog and it runs several at once. The part that matters is the ending: when an agent says it is finished, Swarm doesn't take its word for it — it re-runs your tests itself, checks the pull request really exists, and only then calls the task done. If anything falls short, the task stays yours.

Claims & worktrees

Two agents can't end up in the same checkout, because each task is claimed and gets its own. A claim stays alive while the agent works and lapses when it stops — and if it lapses holding work you haven't committed, Swarm flags it rather than tidying it away.

Workflows

Say once what "shipped" means for your repo — build it, test it, review it, open the pull request — and Swarm walks a task through, step by step. A step that fails stops the line and tells you which one, instead of carrying on and hoping.

  • Ready to work — your local env file is copied over and dependencies are installing before the agent even starts.
  • Handoffs — every session that pauses leaves one; the next session in that worktree is told at start.
  • Ask the human — the question lands on the session page with its options as buttons; the answer reaches the agent by itself.
  • Agents talk to each other — message another session, or whoever is holding a task, and it arrives exactly once.
  • Ports that stay yours — dev servers and databases are held by name, so one agent can't kill another's.
  • PRs, one queue — GitHub and GitLab side by side, merged from here. Swarm uses the CLI you're already signed into and stores no tokens.

Guard

The “never do X” paragraph in your CLAUDE.md is a wish. Swarm turns it into a permission decision at the hook, and records every one.

Rules instead of prose

A sweeping git add -A while a colleague's session shares the checkout, a kill-by-name that catches the wrong process, a write into someone else's worktree — each one gets a prompt or a refusal the moment it is attempted, and a record of what was tried. Guardrails against accidents, not a sandbox: if the daemon is unreachable the hook fails open, so your work never blocks on Swarm.

Codify it, then try it on history

Turn any incident into a .swarm.toml rule and a CLAUDE.md lesson with one click. Dry-run replays your recorded tool calls under modes you pick and shows exactly what would have fired — before you switch anything on.

Policy that holds when the daemon doesn't

An org can lock the rules that matter in a signed policy.toml the layers below cannot override — and while a rule is locked the hook enforces it from a cached snapshot even if the daemon is down.

  • Permission broker — a spawned agent's prompts go through your rules, not a terminal nobody is watching.
  • Run profiles — no-edits and read-only narrow what a spawned agent may do at all.
  • Audit log — every record carries who did it; export as JSONL, CSV or JSON.
  • Privacy — don't store prompts or reasoning at all, redact by regex; keys and bearer tokens always scrubbed.
  • Budgets — daily / weekly ceilings that warn, ask before every spending tool, or stop the runs.
  • Model allow-list — allow = ["claude-*"], org-lockable; dispatch refuses anything else.

One optional file

Swarm is repo-agnostic on purpose: it works on an empty folder, and the only file it ever wants inside your repository is this one — committed, so the repo declares its own rules.

.swarm.toml — rules, gates, warm worktrees, the backlog and a budget. Global defaults live in ~/.swarm/config.toml; an org policy can lock any of it. Bad config never takes the daemon down.

[rules]                      # "ask" | "deny" | "off"
shared_tree     = "deny"     # broad `git add -A` in a shared checkout
destructive_git = "ask"      # reset --hard, checkout ., clean -f …
pattern_kill    = "ask"      # pkill -f and friends
protected_ports = "ask"
no_foreign_worktree = "ask"  # writes into someone else's worktree

[gates]                      # executed, not vouched for
required = ["tests", "review"]
[gates.tests]
cmd = "bun test"

[worktree]                   # start every worktree warm
copy  = [".env.local"]
setup = "bun install"

[tasks]
source = "docs/plan.md"      # or "github" / "linear"

[budget]
daily = 25                   # USD; warn | ask | stop

How it fits together. One daemon, one SQLite file under ~/.swarm, a dashboard on 127.0.0.1. The hook fails open: if the daemon is down, nothing blocks your work.

  • Uninstalling leaves your repositories byte-for-byte untouched.

Six agents, one ledger

Claude Code through its hooks and transcripts — the full picture, rules and MCP included. The other five are read from the session logs they already write, so they land on Fleet, Timeline, Spend and Outcomes with real tokens and real cost.

  • Claude Code — hooks, transcripts, MCP tools, rules, spawned runs.
  • Codex CLI — ~/.codex rollout logs; MCP registered by swarm install.
  • Gemini CLI — ~/.gemini chat recordings; MCP registered too.
  • Grok — ACP updates.jsonl.
  • Aider — its own .aider.chat.history.md, with the exact cost it reports.
  • opencode — its SQLite database, read-only.
And when it outgrows one laptop

swarm-teamd is a second, self-hosted service your machines forward to: audit events, spend rollups and claims — never transcript text unless a machine opts in, and always after your redaction rules. You get one view of the fleet (machines, cluster-wide claims, spend by person and by project), a claim taken on one laptop is refused on another with the holder's name, org policy is ed25519-signed and verified against a key pinned at login, and monthly chargeback exports come out by user, machine, model or ticket id. Every laptop stays local-first and keeps working offline.

One machine is free and always will be. The team daemon is the single source-available package (FSL-1.1-ALv2, Apache-2.0 after two years); everything else is Apache-2.0. Teams guide →
