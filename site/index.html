See every agent. Stop the collisions.

One daemon watches every agent session on your machine, keeps the ledger of who holds which task, worktree and port, spawns and gates agents of its own — and turns “never do X” from a line in CLAUDE.md into a permission decision.

Local-first. No account, no telemetry, nothing added to your repositories.

Observe

Run four agents at once and you lose the thread by lunchtime. Swarm reads the hooks and transcripts they already write — nothing to instrument, nothing added to your repo.

Fleet, live

Every session on the machine, streaming: agent, branch, the tool it is running right now, model, output tokens, context size, cost, age. Across every repo, with zero instrumentation.

Replay, and resume

Step through an agent's tool calls one at a time with the full input and output of each. A session that died gets Resume where it died — a fresh run from its handoff and last actions.

Collisions, before they happen

A live graph of running sessions against the files they touch. A file two sessions hold with at least one writer turns red — that's tomorrow's merge conflict, on screen while you can still move someone.

Stuck detection

The daemon watches for repeat-and-failing loops and all-failing streaks and marks the session Stuck, with a desktop notification. Deliberately conservative — polling git status never counts — and nothing is ever interrupted.

  • Timeline — session lanes per project, coloured by agent, with a tick per turn and a claims lane underneath.
  • Session detail — the reasoning stream beside the numbers: cost per turn, cache hit rate, thinking share, tool mix.
  • ⌘K everywhere — a palette over every view, project and session, falling through to full-text search.
  • Real data grids — sort, resize, reorder, filter, persisted layouts. Light and dark.

Coordinate

A fail-closed ledger so parallel agents can't clobber each other — and so the next session picks up where the last one stopped instead of re-reading the repo.

Claims & worktrees

A task is claimed into its own isolated git worktree. Leases renew themselves on activity; an expired lease whose worktree still holds uncommitted or unpushed work is flagged orphaned — and nothing is ever removed behind your back.

Warm worktrees & handoffs

New worktrees start with your .env.local copied and bun install already running. Every session that pauses leaves a handoff — files edited, last verification command, what remains — and the next session in that worktree is told at start.

Gates that actually run

[gates.tests] cmd = "bun test" is executed inside the task's worktree, not vouched for: exit 0 passes, the output tail is the evidence, the latest run decides and failures are never deleted. A built-in review gate spawns a read-only reviewer over the diff.

Runtime resources

Dev servers, databases and ports held as named singletons — fail-closed, pid- and lease-tracked. A held port is protected from every other agent's kill with no config, and nothing is ever killed by command pattern.

Drive

Swarm doesn't only watch agents — it starts them, in a claimed worktree, under the same rules as your interactive sessions, and reports what actually came out.

Run & dispatch

swarm run --task X claims the task and spawns an agent in its worktree — steer it by stdin, stop it by pid. swarm dispatch --ready gives every claimable task its own run, N at a time, then re-runs the gates and looks for the PR: done, gates-failed, no-pr or crashed.

Workflows

steps = ["implement", "gate:tests", "gate:review", "pr"] in one config file, and the daemon advances it: run steps spawn an agent, gate steps must pass to continue, pr pushes the branch and opens the pull request. A failed step stops and says so.

Agents that talk — to you and each other

An agent that hits a decision only a person can make asks for one: the question lands on the session page with its options as buttons, and the answer reaches the agent by itself. Agents message each other by session, by task holder, or by "lead" — delivered exactly once.

Permission broker

A spawned agent's permission prompts go through your rules instead of a terminal nobody is watching: a deny auto-denies with the reason, an ask becomes an Allow / Deny card on the session, everything else proceeds. Profiles (no-edits, read-only) narrow what it may do at all.

Guard

The “never do X” paragraph in your CLAUDE.md is a wish. Swarm turns it into a permission decision at the hook, and records every one. Guardrails against accidents — not a sandbox.

Rules & incidents

A broad git add -A while another live session shares the checkout, a pkill -f, a write into a worktree someone else holds, freeing a protected port — asked or denied at the hook, each one recorded with the rule, the command and the session.

Codify it, then try it on history

Turn any incident into a .swarm.toml rule and a CLAUDE.md lesson with one click. Dry-run replays your recorded tool calls under modes you pick and shows exactly what would have been asked or denied — before you switch anything on.

Policy that holds when the daemon doesn't

An org can lock the rules that matter in a signed policy.toml the layers below cannot override. While a rule is locked, the hook enforces it from a cached snapshot even if the daemon is unreachable — everything else still fails open, so your work never blocks on Swarm.

Audit & privacy, on your terms

Every ledger record carries who did it; export the whole audit log as JSONL, CSV or JSON. Choose not to store prompts or assistant text at all, redact by regex, and know that API keys and bearer tokens are always scrubbed.

Measure

What today cost, while it is still today — and whether the code an agent wrote survived contact with main.

Spend, by task

Cost and tokens by day, agent, model, project — and by task, matched through the claim. Plus a context-budget table that ranks sessions by how much context they re-read, and per-repo ceilings that warn, ask before every spending tool, or stop the runs outright.

Outcomes

Did the work survive? Sessions join to a branch, the branch to its PR, the PR to merged or reverted — scored per model and per agent: merge rate, median time from session start to merge, and dollars per merge. The one number that says which agent is worth it.

PRs, one queue

GitHub and GitLab in a single list, read through the gh / glab you are already logged into — checks, review state, mergeable — and merge on green from the dashboard. Swarm stores no forge tokens.

Memory & stats

Full-text search over everything Swarm remembers — handoffs, incidents, gate runs, what sessions actually said. And the long view: all-time spend and tokens, streaks, a year of activity, record holders.

One optional file

Swarm is repo-agnostic on purpose: it works on an empty folder, and the only file it ever wants inside your repository is this one — committed, so the repo declares its own rules.

.swarm.toml — rules, gates, warm worktrees, the backlog and a budget. Global defaults live in ~/.swarm/config.toml; an org policy can lock any of it. Bad config never takes the daemon down.

[rules]                      # "ask" | "deny" | "off"
shared_tree     = "deny"     # broad `git add -A` in a shared checkout
destructive_git = "ask"      # reset --hard, checkout ., clean -f …
pattern_kill    = "ask"      # pkill -f and friends
protected_ports = "ask"
no_foreign_worktree = "ask"  # writes into someone else's worktree

[gates]                      # executed, not vouched for
required = ["tests", "review"]
[gates.tests]
cmd = "bun test"

[worktree]                   # start every worktree warm
copy  = [".env.local"]
setup = "bun install"

[tasks]
source = "docs/plan.md"      # or "github" / "linear"

[budget]
daily = 25                   # USD; warn | ask | stop

How it fits together. One daemon, one SQLite file under ~/.swarm, a dashboard on 127.0.0.1. The hook fails open: if the daemon is down, nothing blocks your work.

           swarmd ──▶ SQLite (~/.swarm) — the only place state lives

              └──▶ swarm run / dispatch ──▶ an agent in a claimed worktree
  • Identity is the git common dir, so every worktree of a repo maps to one project.
  • Hooks are installed once, user-wide — every session on the machine reports in.
  • Uninstalling leaves your repositories byte-for-byte untouched.

Six agents, one ledger

Claude Code through its hooks and transcripts — the full picture, including rules and MCP. The other five are observed by reading the session logs they already write, so they show up on Fleet, Timeline and Spend with real tokens and real cost.

  • Claude Code — hooks, transcripts, MCP tools, rules, spawned runs.
  • Codex CLI — ~/.codex rollout logs; MCP registered by swarm install.
  • Gemini CLI — ~/.gemini chat recordings; MCP registered too.
  • Grok — ACP updates.jsonl.
  • Aider — its own .aider.chat.history.md, with the exact cost it reports.
  • opencode — its SQLite database, read-only.
And when it outgrows one laptop

swarm-teamd is a second, self-hosted service your machines forward to: audit events, spend rollups and claims — never transcript text unless a machine opts in, and always after your redaction rules. You get one view of the fleet (machines, cluster-wide claims, spend by person and by project), a claim taken on one laptop is refused on another with the holder's name, org policy is ed25519-signed and verified against a key pinned at login, and monthly chargeback exports come out by user, machine, model or ticket id. Every laptop stays local-first and keeps working offline.

One machine is free and always will be. The team daemon is the single source-available package (FSL-1.1-ALv2, Apache-2.0 after two years); everything else is Apache-2.0. Teams guide →
