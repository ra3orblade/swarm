Swarm v0.8.0 — the trust release.

Monday. Security wants to know what the agents were allowed to do last week, and who approved what.

You run `swarm audit export --since 7d --format csv`. Every claim, every denied command, every gate verdict, every "allow" a human clicked — with who did it. Prompt text was never stored; the one API key an agent pasted into a shell command reads `[redacted]`.

Then they ask the real question: what stops someone from turning the rules off? You show them `~/.swarm/policy.toml`:

locked = ["rules.destructive_git", "rules.protected"]

Repo config can't override it. `SWARM_GUARD=off` is ignored. Deleting the hook opens an incident. And if the daemon is down, the shim still enforces exactly those rules from a hashed cache — fail-closed where it matters, fail-open everywhere else.

Last thing: the PR an agent opened at 2am. `[gates.review] builtin = "review"` had a second agent read the diff — read-only, fixed rubric — and fail it for a major finding before anyone saw it.

Local-first, open source, no account. One command:
bunx @ra3orblade/swarm setup

Release notes: https://getswarm.vercel.app/changelog

## Thread (optional follow-ups)

- The daemon has a credential now: `~/.swarm/token`, sent by the CLI, MCP server, hook shim and `swarm ui`. Loopback may skip it by default; `[daemon] auth = "required"` flips that. Nothing that isn't loopback ever skips it.
- Every record carries an actor — human, agent, run or daemon — and the schema is versioned: old rows were back-filled, `swarm doctor` shows `schema v1`.
- The dashboard stopped being a list of tables: a Board with a KPI strip, a task kanban and a worktree map; one menu per row instead of inline links; project icons (emoji or your logo).
