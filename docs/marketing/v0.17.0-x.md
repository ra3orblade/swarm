Swarm v0.17.0 is out. Codex sessions now get the same treatment as Claude Code ones.

A colleague told me Swarm worked badly with Codex and some of it didn't work at all. They were right. Codex added Claude-style hooks a while ago, and Swarm was still installing just one of them, so Codex got the rules and nothing else. Now it gets session context, permission cards, the repair loop on Stop and messages from other sessions. Codex spend was also 3–10% too high, because Codex writes the same token count twice and Swarm counted both. Upgrading re-reads old sessions to fix that.

Local-first, open source, no account. One command:
bunx @ra3orblade/swarm setup

Release notes: https://getswarm.vercel.app/changelog
Downloads: https://getswarm.vercel.app/#downloads

## Thread (optional follow-ups)

1/ Spend broken down by MCP server, skill and subagent. One of my sessions from last month cost $73, and $34 of that was a single skill. I wouldn't have guessed. An MCP server gets the cost of the turns that called it, which leaves out the cost of carrying its output around afterwards. The view says so.

2/ A workflow can keep watching the PR it opened (`on_fail = "resume"`). If CI fails or a reviewer asks for changes, the task goes back to work in the same worktree with the failure as its prompt, up to two attempts by default. I haven't run it against a real PR yet, so treat it as new.

3/ `[[signals]]` lets you name a pattern to watch for, like an edit followed by `git push --force`, or a session saying "unable to". A hit shows up as an incident on a new Signals view. The same view gives each session a rough 0–100 score from re-reads, failed tool calls, waiting time and gates. The weights are my guess, and it's meant for spotting trends, not ranking anyone.
