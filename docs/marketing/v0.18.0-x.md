Swarm v0.18.0 is out. It now knows what your projects run, and what of it is known to be bad.

There are a lot of security incidents in the package ecosystems at the moment, and Swarm was watching every agent on my machine without knowing what any project actually depended on. So it reads the lockfiles now (bun, pnpm, npm, yarn, uv, poetry, pinned requirements, GitHub Actions), and with one line of config it asks OSV about the exact versions. That line is off by default, because the query is your dependency list. On my own repo it found 19 open advisories, one critical. I had no idea.

An advisory opens an incident, the agent is told about it when its session starts, and an Upgrade button sends an agent into its own worktree to bump the version, run the gates and open a PR.

Local-first, open source, no account. One command:
bunx @ra3orblade/swarm setup

## Thread (optional follow-ups)

1/ A News view. It reads the projects' own security channels, CISA, CERT-Bund and the security press, and shows an item only when it names something the selected project runs. The keywords come from the lockfile, not from a list I maintain. The first run matched every headline because a transitive package is called `which`; now only declared runtime packages count.

2/ You can add your own sources, and check one before you do: the daemon fetches the URL once with the same reader it runs every half hour and tells you whether it parsed as RSS or Atom, or what it got instead. A 403 looks different from a blog that is not a feed.

3/ Two new rules. `vulnerable_install` asks before an agent installs a version with a known advisory, from a table on the machine, never the network. `secret_commit` asks before `git add .env`, and before a commit whose staged diff adds a token — it reads `git diff --cached` at that moment and names the kind of key, never the value.

4/ `swarm security report` prints a markdown page per project: the stack, the advisories with links, what agents reached for in the last two weeks, and the news that matched. I paste it into the weekly note.

5/ One bug the new tests found: the `swarm_context` MCP tool had always answered "nothing to report", because the route was registered twice and the daemon answered from the wrong one. Fixed.
