## Main post

An agent claims a task, gets its own worktree, and starts editing — in the *other* agent's worktree, because a path looked close enough.

Swarm 0.4.0 turns "never touch a worktree you don't hold" from a line in CLAUDE.md into a hook decision. The edit is asked about, or refused, before it lands.

Local-first, open source, one command. getswarm.vercel.app

## Thread

1/ Rules used to watch Bash. Now they watch writes too: `no_foreign_worktree` fires on Write/Edit into someone else's claimed worktree. Holding is inferred from where the session is sitting — the worktree exists because of a claim, so whoever is inside it is the holder.

2/ Flip `claim_required_to_write = "deny"` in `.swarm.toml` and the shared checkout becomes read-only without a claim. Claim a task, get a worktree, write there. Claims stop being bookkeeping.

3/ Your backlog, read, not owned. Point `[tasks] source` at a markdown file with `ID | Task | Depends | Status` tables and the Board shows what's *ready* — todo, deps done, unclaimed — with a Claim button. Agents ask `swarm_next_task`. Swarm's own roadmap is its own task source.

4/ `swarm serve start --name web -- npm run dev`: a free port is allocated, `PORT` is set, the pid and its start time are recorded, and the port is protected from every other session's `kill` with no config. `swarm serve stop` signals that pid and nothing else — never a pattern, never a recycled pid.

5/ Every ask and deny now lands in an Incidents feed you can actually clear. Ack it when you've seen it; the count in the nav is what you haven't.

6/ And once a month, if you like it, the dashboard will ask for a star. Say no once and it never asks again.
