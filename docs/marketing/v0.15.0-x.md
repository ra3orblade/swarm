Swarm v0.15.0 is out. It watched six agents and only enforced its rules on one. Now the rules hold
on Codex, Gemini CLI and Cursor too.

Cursor was the one that surprised me. It imports Claude Code's hooks, so Swarm's hook was already
running inside it — and letting everything through, because Cursor calls its shell tool `Shell`
and sends no session id. Every rule was installed and none of them fired. Swarm reads that payload
now. None of the three can ask you anything from a hook, so a rule set to `ask` refuses there and
tells the agent to hand the command over to you.

Also in this one: five rules for commands you can't take back (`rm -rf` outside the repo,
`terraform destroy`, `curl | sh`, reading `.env`, editing Swarm's own config). They ship off; the
Security view shows what each would have caught on your machine so you can decide. And OTLP
export, if you'd rather look at your agents in your own Grafana.

Local-first, open source, no account. One command:
bunx @ra3orblade/swarm setup

Release notes: https://getswarm.vercel.app/changelog
Downloads: https://getswarm.vercel.app/#downloads

## Thread (optional follow-ups)

1/ After compaction an agent forgets it holds a task and a worktree. Claude Code fires
`SessionStart` again with `source: "compact"`, so Swarm answers it with the claim, the lease and
the handoff again, headed "context was compacted" so the agent knows it is a reminder.

2/ Worktrees Claude Code makes itself (`claude --worktree`, subagents with worktree isolation) are
claimed now, by watching where hooks come from. I looked at the `WorktreeCreate` hook first, but
configuring it replaces Claude Code's own worktree creation, so Swarm doesn't install it.

3/ The team daemon installs without a clone: `npm i -g @ra3orblade/swarm-team`, a ghcr image, or a
binary the app downloads once you accept its license (FSL, not Apache like the rest).
