Swarm v0.18.3 is out. A patch for CPU.

With a few agents running, the machine got hot and Swarm didn't look like the cause in Activity Monitor. It was, though. Every 15 seconds the daemon asked git about every worktree of every project, about 350 processes on my laptop, and that CPU was charged to the git children rather than to Swarm. On top of that, the spend totals were cached "until the next write", and with agents working every hook is a write, so each dashboard poll re-summed the whole history while the agents' hooks waited. I replayed real hook traffic against a copy of my ledger to measure it. The same load now uses about a quarter of the CPU, and hooks answer in 3 ms on average instead of a second. The News view also gets menus in its heading and AI news by default.

Local-first, open source, no account. One command:
bunx @ra3orblade/swarm setup

## Thread (optional follow-ups)

1/ The worktree listing already reports each worktree's HEAD, so a commit or a checkout shows up without asking git anything else. What it can't see is an edit, and edits mostly come from agents, whose hooks now mark the path. An edit made in an editor shows up within five minutes. Removing a worktree still asks git fresh, because that decision refuses on a dirty tree.

2/ Spend splits at local midnight. The days before today don't change during the day, so they're summed once; today's turns are an index range. 116 ms → 3 ms per call, with output byte-identical to the old queries on my ledger.

3/ Smaller ones: session totals are re-summed only for sessions with new turns, the branch of a hook's directory comes from .git/HEAD instead of a git process, and price lookups stopped scanning a few thousand model names per turn.
