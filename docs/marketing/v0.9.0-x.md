Swarm v0.9.0 — the crew release.

Tuesday morning. You type one line in .swarm.toml:

steps = ["implement", "gate:tests", "gate:review", "pr"]

`swarm workflow ship checkout` and walk away. An agent implements in its own worktree. The tests run — actually run, not "I ran the tests, trust me". A second agent reads the diff and can say no. The PR opens itself, written from the ledger.

Halfway through, the implementing agent hits something odd and messages you: "Cart tests were flaky before my change — rebase or fix here?" It shows up on your session, and on your phone. You answer; it keeps going.

And the Timeline finally tells the truth: not one smug solid bar, but bursts of ticks and honest idle gaps — you can see the agent think, stall, and resume. Claude, Codex, Gemini and Grok, all on one screen.

New here? `swarm demo` opens a seeded dashboard so you can see all of it before hooking anything up.

Local-first, open source, no account. One command:
bunx @ra3orblade/swarm setup

Release notes: https://getswarm.vercel.app/changelog

## Thread (optional follow-ups)

- Messaging is addressed, not broadcast: `swarm_send` to a session, to whoever holds a task, or to "lead" — you. Delivered exactly once, on the next tool call or straight into a spawned run's stdin.
- A failed workflow step doesn't limp on: incident, handoff, stop. A daemon restart marks in-flight workflows stopped instead of pretending they're alive.
- After `npm upgrade`, the dashboard notices the newer version on disk and restarts the daemon in one click. No more "why am I still on the old build".
