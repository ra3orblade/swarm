## Main post

Two Claude Code sessions, one repo. One ran `git add -A` and quietly swept the other's half-finished work into its commit. We found out an hour later.

Swarm 0.3.0 exists so that never happens again.

Local-first, open source, one command. getswarm.vercel.app

## Thread

1/ The fix isn't a line in CLAUDE.md hoping the model reads it. It's a rule:

```
[rules]
shared_tree = "deny"
```

Next time an agent tries `git add -A` while another session is live in the same checkout, Claude Code gets a real permission denial. Not a suggestion. A no.

2/ Ports, same story. Agent A starts the database: `swarm res acquire db --port 5432`. Ten minutes later agent B decides the port is "stuck" and reaches for `lsof -ti:5432 | xargs kill`. Blocked. You configured nothing — holding the port was enough.

3/ Every one of those moments lands on the Board: which rule, which command, which session, when. You find out the same minute, not during code review on Friday.

4/ And the end of the loop: every open PR across GitHub and GitLab in one queue, read through the `gh` and `glab` you already have. Green and mergeable? One click. Swarm never sees a token.

5/ Everything runs on your machine. No account, no telemetry, nothing leaves.
