Swarm v0.3.0 — the coordination release.

Running several Claude Code sessions on one repo? This is the version where they stop stepping on each other:

→ Rules you configure, not prose: shared_tree / destructive_git / pattern_kill / protected_ports, each ask | deny | off per repo in .swarm.toml. "deny" is a real permission denial the agent can't talk past.
→ Runtime resources: an agent acquires "db" on :5432 and every other agent's `lsof | kill` on that port gets stopped. Fail-closed, pid- and lease-tracked.
→ Incidents: every ask/deny recorded, on the Board.
→ PRs: one merge queue across GitHub + GitLab via your own gh/glab. Merge on green from the dashboard. No tokens stored.

Plus Board, Stats, a real data-grid everywhere, Check for Updates in the desktop app, and docs + release notes on the site.

Local-first, open source, no account. One command:
bunx @ra3orblade/swarm setup

Release notes: https://getswarm.vercel.app/changelog

## Thread (optional follow-ups)

- Why rules: a parallel session's `git add -A` swept another agent's work this week — while the daemon was down and the hook failed open. 0.3.0 closes both: the hook falls back to the default port, and shared_tree can be `deny`.
- Board view: claims, worktrees, resources and incidents for the selected project; Fleet is sessions only again.
- Stats: all-time tokens, spend, streaks, activity calendar — DST-immune daily buckets.
- Data-grid everywhere: sort, resize, reorder, per-column filters, persisted layouts — identical on every table including Spend.
- Design tokens: the dashboard CSS has zero raw hex / font-size / duration values; docs/12 has the drift grep.
