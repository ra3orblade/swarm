## Main post

You tell Swarm to run a task. It claims the ticket, opens a fresh worktree, and starts an agent inside it. The agent goes to `pkill -f node` — Swarm stops, shows you the command and why it's dangerous, and waits for you to say yes or no.

That's Swarm 0.5.0. It doesn't just watch your agents now. It drives them, and it holds the door.

Local-first, open source, one command. getswarm.vercel.app

## Thread

1/ `swarm run --task login-form --prompt "…"` claims the task, spawns `claude -p` in its worktree, and streams it into the same dashboard as every other session. Steer it by typing into a box. Stop it and the process dies by pid — never by pattern, so it can't take a neighbour down with it.

2/ Every permission prompt the spawned agent hits runs through the same rules that guard your own sessions. A denied command is denied with a reason the agent can read. Anything the rules aren't sure about waits for you on the session page with Allow / Deny — not on a terminal you closed an hour ago.

3/ The primitives that make leaving a run alone safe: the lease renews itself while the agent works, so it never expires mid-task. If it does end with unfinished work in the tree, that becomes an incident instead of a silent orphan.

4/ Before it stops, the agent leaves a handoff — done, remaining, files, how to verify. The next session that opens in that worktree reads it automatically. Pick up exactly where the last one left off, no archaeology.

5/ And a gate is a promise with a receipt: `swarm gate record login-form review pass --rubric "…"`. No rubric, no pass. The latest run decides, the failures stay on the record.

6/ Also this release: the MCP tools actually connect now (`claude mcp list` → swarm ✔). Run agents straight from the Board. And the website finally has real screenshots.
