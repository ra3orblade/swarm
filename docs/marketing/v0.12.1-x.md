Swarm has been telling me my agents' worktrees hold 50 GB, and offering nothing to do about it.

Turns out 31 GB of that is node_modules and Rust target dirs — stuff a rebuild recreates.

v0.12.1 measures that separately and offers to clear it. Your branch and anything uncommitted stay exactly where they are.

bunx @ra3orblade/swarm setup

## Thread (optional follow-ups)

1. The other half of the problem: a worktree had to sit untouched for seven days before Swarm called it stale. On a machine where work lands daily that never happens, so the report said "50 GB held, 0 reclaimable" — which reads as broken, not cautious. Two days now.

2. And a branch merged by squash was never recognised as merged. `merge-base --is-ancestor` is the right test for a merge commit and useless for a squash: the original commits never become ancestors, so the branch reads as unfinished forever. It asks `git cherry` too now, which compares by patch.

3. Clearing build output is deliberately not the same act as removing a worktree. It refuses the main checkout, anything a claim holds, and anything with a live session in it — those mean a build is probably running.
