Swarm v0.7.0 — the orchestrate release.

Friday, 6pm. Three tasks are ready in the backlog. You type `swarm dispatch --ready` and go make dinner.

Each task gets its own worktree — deps already installed, .env.local already copied — and an agent that's told: work here only, commit as you go, run the gates, hand off, open the PR, and if you hit a decision only a human can make, ask.

One of them does. Your phone buzzes: "Postgres or SQLite for the cache?" Two buttons. You tap one between stirring. The agent picks up the answer on its next tool call and keeps going.

When the runs end, Swarm doesn't take the agent's word for anything. It re-runs the test gate itself, checks GitHub for the PR, and writes the verdict: two done, one gates-failed — with the log, the worktree kept, and a "resume where it died" button.

And the bill stayed under the $25 you put in `[budget]`. Past that, every edit would have asked first.

Local-first, open source, no account. One command:
bunx @ra3orblade/swarm setup

Release notes: https://getswarm.vercel.app/changelog

## Thread (optional follow-ups)

- Gates that run themselves: `[gates.tests] cmd = "bun test"` — the rubric is the command and how it ended, the evidence is the output tail. An agent can record `review pass`; it can't fake `bun test`.
- `swarm wt`: worktrees without a task, drift against main (N behind / merged), Diff on every row, Open PR prefilled from the task + handoff + gates, `gc` for the merged ones.
- `swarm_context`: an agent can re-read what it holds, its handoff, gate status and rule modes mid-session — and the same MCP server now registers with Codex CLI and Gemini CLI, so they get the tools too.
- Run profiles: `--profile no-edits` for reviewers and triage runs, `read-only` for "just tell me".
