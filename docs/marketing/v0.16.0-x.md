Swarm v0.16.0 is out. The five "commands you can't undo" rules from 0.15 now ask by default.

They shipped off so I could see what they'd catch first. Two weeks of my own agents' commands, about 13k of them, would have triggered roughly 160 prompts, and most were wrong: `curl … | python3 -c "…"` read as piping a download into a shell, `rm -rf "$S"` flagged even when `S` was set two words earlier, `2>/dev/null` counted as writing to config. After fixing those, 62 are left, and nearly all of them are agents reading `.env`, which is what the rule is for.

Also in this one: `swarm run --sandbox` wraps a spawned agent in Anthropic's sandbox-runtime, so it can only write to its worktree and only reach hosts you allow. And workflows can run on a cron, e.g. your gates on main every night.

Local-first, open source, no account. One command:
bunx @ra3orblade/swarm setup

## Thread (optional follow-ups)

1/ A second model can look at each permission prompt and write its verdict on the card (`[broker] reviewer = "advise"`). The first real test hung for 90 seconds: the reviewer is itself a `claude -p`, so Swarm's own hooks fired inside it and held it open. It runs with hooks disabled now.

2/ Scheduled PR reviews post a plain comment at most once per push, never approve, and skip forks. A schedule does nothing until you arm it, because Swarm picks up every repo you've run a session in, and a cloned repo shouldn't be able to comment on PRs by itself.

3/ When the same tool call fails three times across two sessions, it shows up in the Gates view with an Open issue button that files it on your GitHub or Linear tracker.
